# Abhaengigkeiten dieses Projekts - festgenagelt, nicht als Spanne (PJ11).
#
# Bis zum 08.09.2026 stand hier "Django>=5.2,<7.0" und zehnmal dasselbe Muster.
# Damit baut jedes Deploy das, was an seinem Tag gerade neu ist: Der Container,
# der abends hochfaehrt, kann eine andere Django-Fassung tragen als der, gegen
# den morgens 490 Tests gruen waren. Faellt danach etwas aus, ist die Ursache
# nicht im Diff zu finden - es hat sich ja nichts geaendert.
#
# Deshalb steht in jeder Zeile "==". Die Fassungen sind die, die am 08.09.2026
# installiert waren und gegen die die Testsuite gruen lief; sie entsprechen
# zugleich dem, was die alten Spannen an diesem Tag aufgeloest haetten - der
# Umstieg ist also kein Versionssprung, sondern nur das Festhalten des Standes.
#
# **Diese Datei IST das Lockfile.** Railway baut per NIXPACKS und installiert
# genau sie; ein zweites, danebenliegendes lock-File wuerde von niemandem
# gelesen und nur so aussehen, als sei der Bau reproduzierbar. Aus demselben
# Grund stehen unten auch die mitgezogenen Abhaengigkeiten - ohne sie waere die
# Haelfte des Baums weiterhin frei beweglich.
#
# AKTUALISIEREN: Fassung hier aendern, dann lokal installieren und
#   python manage.py check ; python manage.py test ; python manage.py check_seo
# laufen lassen. ``PinsPassenZurUmgebung`` in apps/core/tests/test_requirements.py
# wird rot, solange die installierte Fassung von der eingetragenen abweicht -
# das ist der Zweck, nicht ein Fehler.
#
# WAS DIESE DATEI NICHT LEISTET: Sie prueft keine Pruefsummen (kein --hash) und
# sagt nichts ueber Sicherheitsluecken. Eine festgenagelte Fassung ist eine
# bekannte Fassung, keine gute - wer nie aktualisiert, bleibt auf alten Luecken
# sitzen.
